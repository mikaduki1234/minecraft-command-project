# Minecraft Command Project

Minecraft Bedrock Editionで制作した、サーバー向けゲームシステムの個人開発記録です。

Minecraftのコマンドを中心に、ショップや所持金管理などのゲームシステムを設計・実装しました。

## 開発概要

- 開発環境：Minecraft Bedrock Edition
- 開発形態：個人開発
- 開発開始：2026年7月
- 主な技術：Minecraft Commands / Scoreboard / Tag / NPC / scriptAPI

## 実装したシステム

### アイテム売却システム

プレイヤーが所持しているアイテムを売却し、ゲーム内通貨へ変換するシステムを制作しました。

同じ種類のアイテムが複数のインベントリスロットに分かれている場合でも、アイテム種類ごとに集計して処理できる構造を採用しています。更にはプレイヤーに配慮する形で希少性の高いアイテムは個別で売れるように設定しています。

### 購入システム

ゲーム内通貨を使用してアイテムを購入できるシステムを制作しました。

商品の価格や名前などをまとめて管理し、商品を追加する際の修正箇所を減らすことを意識しました。

### NPCショップ

NPCを入口として、売却・購入・価格確認などのゲーム内機能へアクセスできる構造を制作しました。
また、プレイヤーの体験を損なわせないために実際にプレイヤー側としてテストを行い、ストレスがかかる形のUIを見直しました。

### 価格表

販売対象となるアイテムの価格を一覧で確認できるシステムを制作しました。

### 所持金管理

Scoreboardを利用してプレイヤーごとのゲーム内通貨を管理しています。

### タグを利用した処理制御

プレイヤーに付与されたタグを処理開始のトリガーとして利用し、NPCなどからゲームシステムへ処理を渡す構造を採用しました。

## 設計上意識したこと

### アイテムの名前とその他のUIが被らないように2つのUIを統合することによって、プレイヤーのゲーム体験をよりよくするために設計しました。

### データの一元管理

アイテムの名前や価格などをまとめて管理し、商品を追加・変更する際に複数箇所を書き換える必要ができるだけ発生しないように設計しました。

### マルチプレイを意識した処理

複数のプレイヤーが同時に利用することを想定し、処理対象となるプレイヤーを区別して処理することを意識しました。

### 拡張性

新しい商品やシステムを追加した際に、既存部分を大きく変更せずに拡張できる構造を目指しました。

## 開発を通して学んだこと

Minecraftのコマンドを単体で使用するだけではなく、複数のコマンドやScoreboard、Tag、NPCなどを組み合わせることで、ゲーム内に複雑なシステムを構築できることを学びました。

また、機能を追加することだけでなく、後から修正・拡張しやすい構造にすることの重要性も学びました。
